## 0. 이번 단계

**프록시 + 자체 문항 UI + 커리어넷 검사 실연동 + 결과 화면**까지 만듭니다.

API 스펙 확인이 끝났습니다. 아래는 **실측으로 확정된 사실**이며, 이 문서의 설계는 전부 여기서 나옵니다.

| 확인 항목 | 결과 |
|---|---|
| `relm`(영역) 필드 | **응답에 없음.** 매뉴얼 §1.3 표에는 있으나 실제로는 안 옴 |
| `questions` 응답 필드 | `question`, `answer01~10`, `answerScore01~10`, `tip1~3Score`, `tip1~3Desc`, `qitemNo` (28개) |
| `report` 응답 | `{ inspctSeq, url }` **뿐.** 점수 데이터 없음 |
| q=8 진로개발준비도 | 35문항, 6개 하위영역 |
| 결과 URL의 `seq` | `base64(inspctSeq)` |

**`relm`이 없다는 것이 이 설계의 출발점입니다.** 문항이 어느 하위영역에 속하는지 알 수 없으므로 **영역별 점수를 앱에서 계산할 수 없습니다.**

## 1. 설계 원칙 — 측정 · 행동 · 생성의 분리

이 원칙이 무너지면 구조 전체가 무너집니다.

| | 무엇을 하는가 | 규준 필요? | 담당 |
|---|---|---|---|
| **측정** | 진로 태도·능력 점수 판정 | 필요 | **커리어넷 API** |
| **행동** | 무엇을 했는지 확인 | 불필요 | 자체 문항 (트랙 B) |
| **생성** | 사용자 언어를 정리해 되돌려줌 | 해당 없음 | 자체 문항 (트랙 A·C) |

자체 문항은 타당화 절차를 거치지 않았습니다. **측정은 전부 커리어넷에 맡기고, 자체 문항은 행동 확인과 서술 정리만 담당합니다.**

## 4. 백엔드 프록시

### 라우트

| 메서드 | 경로 | 역할 |
|---|---|---|
| GET | `/api/inspect/questions?q={번호}` | 문항 조회 (캐시) |
| POST | `/api/inspect/report` | 결과 생성 |
| GET | `/api/health` | 헬스체크 + 키 만료 잔여일 |

### 커리어넷 엔드포인트

```
GET  https://www.career.go.kr/inspct/openapi/test/questions?apikey={KEY}&q={번호}
POST https://www.career.go.kr/inspct/openapi/test/report
```

### 화이트리스트 필수

`q`를 그대로 통과시키면 우리 키로 아무 검사나 긁어갑니다.

```ts
const ALLOWED_TESTS = [6, 8, 24, 25, 35, 36] as const
```

### 검사번호

| 번호 | 검사 | 대상코드 |
|---|---|---|
| 6 | 직업가치관 – 대학생·일반 | 100208 / 100209 |
| **8** | **진로개발준비도 – 대학생** (35문항, 6영역) | 100208 / 100209 |
| 24 / 25 | 직업가치관 – 중 / 고 | 100206 / 100207 |
| 35 / 36 | 진로성숙도 – 중 / 고 | 100206 / 100207 |

`gender`: `100323` 남 · `100324` 여

### 문항 캐싱

문항은 거의 바뀌지 않습니다. **TTL 24시간 이상**으로 캐시하세요. 매뉴얼에 "이용량에 따라 사용이 제한될 수 있습니다"라고 명시돼 있습니다. 이번 단계는 인메모리로 충분합니다.

### 키 만료

유효기간 **2년**입니다. 만료되면 서비스 전체가 멈춥니다. `/api/health`가 `CAREERNET_KEY_EXPIRES_AT` 기준 잔여 일수를 반환하고, **60일 미만이면 경고 레벨**로 응답하세요.

```bash
CAREERNET_API_KEY=
CAREERNET_KEY_EXPIRES_AT=   # ISO date
```

`.env.example`을 만들고 실제 값은 커밋하지 마세요.

### 에러 전파

응답의 `SUCC_YN`이 `N`이면 `ERROR_REASON`을 **서버 로그에만** 남기고 클라이언트에는 일반화된 메시지를 반환하세요.

## 5. 검사 실시 UI

문항을 API에서 받아 **우리 UI로** 보여줍니다. 커리어넷 페이지로 보내지 마세요.

### answers 조립

```
"1=5 2=7 3=4 ..."   // 공백 구분, 문항번호=선택값
```

**배열 순서 기준으로 1부터** 매깁니다. `qitemNo`는 영역별 시퀀스라 답변 순번과 다를 수 있으므로 **`qitemNo`를 답변 번호로 쓰지 마세요.** 선택값은 `answerScoreNN` 값을 그대로 씁니다.

### 특수 문항

| 검사 | 처리 |
|---|---|
| 24, 25 | 49번은 3개 선택을 쉼표로 — `49=8,1,4` |
| 35 | 13번은 순위 2개. 답변 8(기타)은 주관식 — `13=1,8:방송계열` |
| 36 | 13번은 순위 2개. 답변 9(기타)는 주관식 — `13=1,9:예체능` |

주관식 답변에 **띄어쓰기가 들어가면 안 됩니다.** 입력값에서 공백을 제거하세요.

이 규칙은 `apps/web/src/lib/answers.ts`에 검사번호별 설정으로 두고 UI가 그걸 읽어 입력 컴포넌트를 바꾸게 하세요. 조건문을 화면 곳곳에 흩뿌리지 마세요.

### 진행 상태

35~63문항이라 중간 이탈이 발생합니다. **문항 하나 답할 때마다 localStorage에 저장**하고 재진입 시 이어서 진행할 수 있어야 합니다.

### `startDtm`

검사 **시작 시각**을 밀리초로 기록해 `report`에 보냅니다. 재진입해도 최초 시작 시각을 유지하세요.

## 6. 결과 화면 — relm 없는 구조

### 원칙

**점수 판정은 커리어넷이, 서술 정리는 우리가.** 두 결과를 한 화면에 나란히 놓되 우리가 점수를 해석하지 않습니다.

```
[우리 화면]
  ├─ 자체 문항 응답 정리        ← 우리가 만듦
  ├─ "가장 낮게 나온 영역은?"    ← 사용자에게 물어봄
  ├─ 그 영역 기준 후속 서술      ← 연결 장치
  └─ [정식 결과표 보기] 버튼     ← 커리어넷 URL (웹뷰)
```

### 핵심 장치 — 영역 되묻기

점수 데이터가 안 들어오므로 **사용자에게 직접 묻습니다.**

1. `report` 후 결과표를 웹뷰로 보여줌
2. 돌아오면 6지선다: **"여섯 개 중에 제일 낮게 나온 게 뭐야?"**
3. 선택한 영역으로 자체 서술 문항을 라우팅하고 후속 대화를 이어감

진로개발준비도(q=8)의 6개 영역입니다. **결과표에서 확인된 값이므로 상수로 두어도 됩니다.**

```ts
const READY_AREAS = [
  '자기이해', '전공 직업지식', '진로결정확신도',
  '의사결정자신감', '관계활용자신감', '구직준비도',
] as const
```

> 다른 검사의 영역 목록은 아직 확인되지 않았습니다. 확인 전까지 `// TODO(probe):` 주석을 달고 되묻기 단계를 건너뛰세요.

### 결과 URL 보관

**URL 전체를 저장하세요.** `inspctSeq`만으로 재구성하지 마세요 — 결과 페이지 경로가 검사마다 다릅니다.

```
진로개발준비도  /cloud/w/inspect/ready/report?seq=...
매뉴얼 예시     /inspct/web/psycho/vocation/report?seq=...
```

`report` 응답의 `url`을 그대로 보관하고 그대로 여세요.

## 7. 결과 표현 규칙

### 자체 문항 결과에 쓰면 안 되는 것

"검사", "진단", "측정", "높음/보통/낮음", "상위 N%", "N점", "당신의 유형은 X입니다".

**경계선은 단정하느냐에 있습니다.**

```
❌ "너는 진로성숙도가 낮은 편이야"
⭕ "진로를 구체적으로 그려본 경험은 아직 많지 않은 것 같아. 이런 걸 해보면 어떨까?"
```

커리어넷 결과표는 공인 검사이므로 등급 표기가 가능합니다. **결과 화면에서 두 출처를 시각적으로 구분**해, 사용자가 어느 쪽이 공인 점수인지 알 수 있게 하세요.

### 트랙별 산출물

- **트랙 A** — 영역별로 사용자가 한 말을 묶어 보여줌. 판정 문구 금지
- **트랙 B** — `staging`으로 단계 1개, `bottlenecks`로 병목. **`maxDisplay`(=2) 초과 노출 금지.** 체크 개수를 점수로 환산하지 마세요
- **트랙 C** — `coverLetterMap` 기준으로 주제별 정리. 산출물은 **성찰 자료이지 자기소개서가 아닙니다.** 그대로 옮겨 쓸 수 있는 글로 제시하지 말고, **대신 작성하지도 마세요.** 사용자가 한 말을 묶는 선에서 멈춥니다

미성년자와 취업 스트레스 상황의 사용자가 대상입니다. 아래 지점에서 어려움을 시사하는 응답이 나올 수 있습니다.

- 결과를 단정적으로 제시하지 말고 상담 자원 안내 분기를 둘 것

- 해당 문항 응답을 근거로 부정적 판단 문구를 생성하지 말 것

import content from '@/data/career_content_v1.json'
const items = content.tracks[trackId].data.items

### 트랙 A — `teen` (24문항, 반말)

- 순서는 `data.recommendedOrder`
- **꼬리물기는 조건부.** `data.followupPolicy.triggers` 참조 — 응답 10자 미만, 회피 응답(`몰라`/`없어`/`그냥`)일 때만 발동. 분류 신뢰도 조건은 이번 단계 제외 (`// TODO:`)
- 순서를 바꿀 경우 `probeType`으로 같은 유형이 연속되지 않는지 확인

### 트랙 B — `jobseeker_behavior` (14문항, 반말)

- **단일 화면 다중선택 체크리스트.** 하나씩 묻지 마세요
- `F1`은 기준 기간이 다름(최근 1개월). `separate: true`이므로 분리 제시

### 트랙 C — `jobseeker_narrative` (12문항, 해요체)

- 순서는 `data.flow.recommendedOrder`
